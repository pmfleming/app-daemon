## Ranked five follow-ups from post-initial review

1. **Overflow-safe hardware totals.** GPU memory region sums and RAPL zone sums
   use unchecked integer addition despite saturating surrounding counters.
   Reproduce overflow, retain counter wrap/baseline semantics, and saturate totals.
2. **Reuse history SQL shapes.** `insert_resource` effort ~81,992 and
   `sql_summary` ~93,518 include rebuilding fixed column/placeholder/aggregate
   text on each point/page. Cache immutable statement text, retain parameters,
   transactions and schema; make storage's actual impl owner explicit.
3. **Index restored-root reassignment.** Every retained identity scans window
   groups looking for any matching PID. Build that PID set once; preserve own
   group precedence, overlapping groups, process start times and owner guards.
4. **Bound disk request selection.** Full due-target sorting runs even with
   both workers occupied. Stop with no capacity and select only the available
   lowest-ID requests; retain bounded channels, backoff and completed values.
5. **Consolidate energy-summary regression ownership.** The standalone energy
   edge matrix exercises a test-only Rust oracle; move its explicit expectations
   into the existing real SQL summary test. Retain independent mathematical
   assertions and demonstrate availability/invalid-value/clipping behavior in
   production SQL while removing the redundant pure-only test owner.

These prioritize concrete safety and repeated runtime work. Architectural
repartitioning and live systemd/desktop tests are outside this bounded campaign.
